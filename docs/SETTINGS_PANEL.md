# 📋 Панель настроек бота

Документация по функционалу настройки параметров бота через команду `/settings`.

---

## 📌 Обзор

Панель настроек позволяет администраторам гибко управлять параметрами расчёта прибыли без изменения кода:
- **Порог процентной ставки** для каждого города
- **Ставки по типам техники** (добавление, удаление)
- **Multibot поддержка** — независимые настройки для каждого города

---

## 🎯 Основные возможности

### 1️⃣ Порог процентной ставки

**Назначение**: Определяет, при какой сумме заказа применяется ставка 50/50 вместо стандартной 40/60.

**Логика**:
- Чистая прибыль **< порога** → Мастер 40%, Компания 60%
- Чистая прибыль **≥ порога** → Мастер 50%, Компания 50%

**Значение по умолчанию**: 7000₽

**Использование**:
1. `/settings` → **⚙️ Порог процентной ставки**
2. Просмотр текущего значения
3. Редактирование → Ввод новой суммы → Подтверждение

**Применение**:
- Настройки хранятся в БД по ключу города (`city_key`)
- Каждый город (city1, city2, ...) имеет независимые настройки
- При завершении заказа автоматически подтягивается актуальное значение

---

### 2️⃣ Ставки по типам техники

**Назначение**: Переопределить стандартную логику расчёта для конкретных типов техники.

**Приоритет**: Ставка по типу техники **выше** порога процентной ставки.

**Примеры**:
- Сантехника: 50/50 (независимо от суммы)
- Водонагреватели: 50/50
- Электрика: 50/50
- Кондиционеры: 55/45 (можно добавить)

**Использование**:

#### Добавление новой ставки:
1. `/settings` → **🔧 Ставки по типам техники**
2. **➕ Добавить ставку**
3. Ввод типа техники (например: "Кондиционеры")
4. Ввод процента мастера (например: 55)
5. Подтверждение

**Примечание**: Процент компании рассчитывается автоматически (100 - процент мастера).

#### Удаление ставки:
1. `/settings` → **🔧 Ставки по типам техники**
2. **🗑 Удалить ставку**
3. Выбор ставки из списка
4. Подтверждение удаления

---

## 🔍 Алгоритм поиска ставки

При завершении заказа система использует **умный поиск** типа техники:

### 3-шаговый алгоритм:

1️⃣ **Точное совпадение** (регистронезависимое)
   - Запрос: "Электрика" → Найдёт "Электрика" в БД
   - Запрос: "электрика" → Найдёт "Электрика" в БД

2️⃣ **Частичное совпадение** (название в запросе)
   - Запрос: "Ремонт кондиционеры на дому" → Найдёт "Кондиционеры"
   - Запрос: "Установка водонагреватели" → Найдёт "Водонагреватели"

3️⃣ **Обратное совпадение** (запрос в названии)
   - Запрос: "Сантех" → Найдёт "Сантехника"
   - Запрос: "Электр" → Найдёт "Электрика"

**Примечание**: Поиск не учитывает падежи русского языка (кондиционеры ≠ кондиционеров).

## 💾 Структура базы данных

### Таблица `city_settings`

Хранит настройки для каждого города:

```sql
CREATE TABLE city_settings (
    id INTEGER PRIMARY KEY,
    city_key VARCHAR(100) UNIQUE NOT NULL,  -- 'default', 'city1', 'city2', ...
    profit_rate_threshold FLOAT NOT NULL DEFAULT 7000.0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**Пример данных**:
```
| id | city_key | profit_rate_threshold | created_at          | updated_at          |
|----|----------|----------------------|---------------------|---------------------|
| 1  | default  | 7000.0               | 2025-12-28 18:21:20 | 2025-12-28 18:21:20 |
| 2  | city1    | 9000.0               | 2025-12-28 18:25:10 | 2025-12-28 18:25:10 |
```

### Таблица `specialization_rates`

Хранит процентные ставки для типов техники:

```sql
CREATE TABLE specialization_rates (
    id INTEGER PRIMARY KEY,
    specialization_name VARCHAR(255) UNIQUE NOT NULL,
    master_percentage FLOAT NOT NULL,
    company_percentage FLOAT NOT NULL,
    is_default BOOLEAN DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    deleted_at DATETIME NULL  -- Soft delete
);
```

**Пример данных**:
```
| id | specialization_name | master_% | company_% | deleted_at |
|----|---------------------|----------|-----------|------------|
| 1  | Сантехника          | 50.0     | 50.0      | NULL       |
| 2  | Водонагреватели     | 50.0     | 50.0      | NULL       |
| 3  | Электрика           | 50.0     | 50.0      | NULL       |
| 4  | Кондиционеры        | 55.0     | 45.0      | NULL       |
```

## 🔄 Приоритет правил расчёта прибыли

Система использует следующий приоритет при расчёте:

### **Приоритет 1**: Ставка из БД (`specialization_rates`)
Если для типа техники найдена ставка → используется она.

**Пример**:
- Заказ: Сантехника, 5000₽ (чистая прибыль)
- Порог: 7000₽ (не применяется!)
- Результат: **50/50** (из БД)

### **Приоритет 2**: Особая логика для холодильников
Прогрессивная ставка:
- Чистая прибыль < 20000₽ → 50/50
- Чистая прибыль ≥ 20000₽ → 60/40

> 📝 **TODO**: В будущем вынести в БД с поддержкой диапазонов сумм

### **Приоритет 3**: Порог процентной ставки
Если нет ставки в БД и не холодильник:
- Чистая прибыль < `profit_rate_threshold` → 40/60
- Чистая прибыль ≥ `profit_rate_threshold` → 50/50

---

## 🎁 Бонусы

После базового расчёта применяются бонусы:

### 1️⃣ Выезд за город
- **+10%** от чистой прибыли мастеру
- Вычитается из прибыли компании

### 2️⃣ Отзыв от клиента
- **+10%** от чистой прибыли мастеру (если `REVIEW_BONUS_ENABLED=true`)
- Вычитается из прибыли компании
- Применяется **только для city1** (согласно текущей конфигурации)

## 📊 Примеры расчётов

### Пример 1: Заказ ниже порога (неизвестный тип)
```
Общая сумма: 6000₽
Расход: 1000₽
Чистая прибыль: 5000₽
Порог: 7000₽

Расчёт:
- 5000 < 7000 → применяется 40/60
- Мастер: 5000 × 0.4 = 2000₽
- Компания: 5000 × 0.6 = 3000₽
```

### Пример 2: Заказ выше порога (неизвестный тип)
```
Общая сумма: 10000₽
Расход: 1000₽
Чистая прибыль: 9000₽
Порог: 7000₽

Расчёт:
- 9000 ≥ 7000 → применяется 50/50
- Мастер: 9000 × 0.5 = 4500₽
- Компания: 9000 × 0.5 = 4500₽
```

### Пример 3: Заказ с ставкой из БД
```
Общая сумма: 8000₽
Расход: 1000₽
Чистая прибыль: 7000₽
Тип техники: Сантехника
Ставка в БД: 50/50

Расчёт:
- Найдена ставка в БД → используется она
- Мастер: 7000 × 0.5 = 3500₽
- Компания: 7000 × 0.5 = 3500₽

Примечание: Порог 7000₽ НЕ применяется!
```

### Пример 4: С бонусом за выезд
```
Общая сумма: 10000₽
Расход: 1000₽
Чистая прибыль: 9000₽
Выезд за город: Да
Порог: 7000₽

Расчёт:
- 9000 ≥ 7000 → 50/50
- Базовая прибыль: Мастер 4500₽, Компания 4500₽
- Бонус за выезд: +10% от 9000 = +900₽
- Итого:
  - Мастер: 4500 + 900 = 5400₽
  - Компания: 4500 - 900 = 3600₽
```

## 🚀 Использование

### Для администраторов

1. Войти в Telegram-бот как администратор
2. Отправить команду `/settings`
3. Выбрать нужное действие в меню

### Для разработчиков

#### Получить текущий порог для города:
```python
from app.database.orm_database import ORMDatabase
from app.utils.helpers import get_city_key

db = ORMDatabase()
await db.connect()

city_key = get_city_key()  # Получаем из ENV_FILE
threshold = await db.get_profit_rate_threshold(city_key)
print(f"Порог для {city_key}: {threshold}₽")
```

#### Найти ставку для типа техники:
```python
equipment_type = "Сантехника"
rate = await db.get_specialization_rate(equipment_type)

if rate:
    master_pct, company_pct = rate
    print(f"{equipment_type}: {master_pct}% / {company_pct}%")
else:
    print("Ставка не найдена, будет использован порог")
```

#### Рассчитать прибыль:
```python
from app.utils.helpers import calculate_profit_split

master_profit, company_profit = calculate_profit_split(
    total_amount=10000.0,
    materials_cost=1000.0,
    has_review=True,
    out_of_city=False,
    equipment_type="Сантехника",
    specialization_rate=await db.get_specialization_rate("Сантехника"),
    profit_rate_threshold=await db.get_profit_rate_threshold(city_key)
)

print(f"Мастер: {master_profit}₽, Компания: {company_profit}₽")
```

## ⚠️ Ограничения

### Склонения слов
Fuzzy поиск НЕ учитывает склонения русского языка:
- ❌ "Ремонт кондиционеров" НЕ найдёт "Кондиционеры"
- ✅ "Ремонт кондиционеры" найдёт "Кондиционеры"

**Рекомендация**: Создавать ставки в именительном падеже, множественном числе.

### UNIQUE constraint
Таблица `specialization_rates` имеет UNIQUE constraint на `specialization_name`:
- Нельзя создать две активные ставки с одинаковым именем
- Даже после soft delete нельзя пересоздать (до hard delete)
