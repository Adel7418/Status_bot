## Введение

Парсер адресов — это модуль системы автоматического распознавания заявок из Telegram сообщений. Основная задача — корректно извлекать адрес из неструктурированного текста, написанного пользователем в произвольной форме.

### Основные файлы

- **`app/services/telegram_parser/patterns.py`** — ключевые слова, регулярные выражения, функция `looks_like_address`
- **`app/services/telegram_parser/parser_service.py`** — основная логика парсинга, класс `OrderParserService`
- **`app/services/telegram_parser/schemas.py`** — модели данных (Pydantic)

---

## Архитектура парсера

```
Сообщение из Telegram
    ↓
OrderParserService.parse_message()
    ↓
1. Разбиение на строки (_split_into_lines)
2. Извлечение телефона (_extract_phone_from_lines)
3. Извлечение времени (_extract_time_from_lines)
4. Разделение на оборудование/проблему и адрес (_split_equipment_and_address)
    ↓
    → looks_like_address() для каждой строки
5. Извлечение типа оборудования (_extract_equipment_type)
6. Извлечение описания проблемы (_extract_problem_description)
7. Валидация через Pydantic
    ↓
ParseResult (success/error)
```

## Функция `looks_like_address`

**Расположение:** `app/services/telegram_parser/patterns.py:181-291`

### Назначение

Определяет, похожа ли строка текста на адрес.

### Алгоритм работы

```python
def looks_like_address(text: str) -> bool:
    # 1. Преобразуем в нижний регистр
    text_lower = text.lower()

    # 2. Исключаем временные индикаторы
    if TIME_PATTERN.search(text) or any(time_keyword in text_lower):
        return False

    # 3. Проверяем наличие адресных ключевых слов
    for keyword in ADDRESS_KEYWORDS:
        if keyword найден в тексте (с учетом границ слов):
            return True

    # 4. Проверяем наличие цифр + букв без слов-индикаторов проблемы
    if есть_цифры AND есть_буквы:
        if есть_паттерн "5-10" или "12/3":
            return True

        if длина < 60 AND нет_слов_проблемы:
            return True

    return False
```

### Параметры и пороги

| Параметр | Значение | Назначение |
|----------|----------|------------|
| Максимальная длина строки | 60 символов | Адреса обычно короткие |
| Слова-индикаторы проблемы | `["не", "течёт", "течет", "шумит", "крутит", "работает", "включается", "выключается"]` | Исключить описания проблем |
| Временные ключевые слова | `["завтра", "сегодня", "послезавтра", "утром", "днём", "днем", "вечером", "ночью", "срочно", "через"]` | Исключить временные индикаторы |

### Эвристики

1. **Ключевые слова имеют приоритет** — если строка содержит "ул.", "д.", "кв." и т.д., это адрес
2. **Цифры + буквы без проблемных слов** — вероятно адрес (например, "Нефтяников 12")
3. **Границы слов** — слово "не" в строке "Нефтяников 12" не считается индикатором проблемы (используется `\b`)
4. **Длина строки** — адреса обычно не превышают 60 символов

## Ключевые слова ADDRESS_KEYWORDS

**Расположение:** `app/services/telegram_parser/patterns.py:74-136`

### Полный список

```python
ADDRESS_KEYWORDS: list[str] = [
    # Улицы
    "улица", "ул", "ул.",

    # Проспекты
    "проспект", "пр", "пр.",

    # Переулки
    "переулок", "пер", "пер.",

    # Проезды
    "проезд", "пр-д",

    # Бульвары
    "бульвар", "б-р",

    # Набережные
    "набережная", "наб", "наб.",

    # Площади
    "площадь", "пл", "пл.",

    # Микрорайоны
    "микрорайон", "мкрн", "мкр", "мкр.",

    # Тракты и шоссе
    "тракт", "шоссе",

    # Дома
    "дом", "д", "д.",

    # Квартиры
    "квартира", "кв", "кв.",

    # Корпуса
    "корпус", "корп", "корп.", "к", "к.",

    # Строения
    "строение", "стр", "стр.",

    # Подъезды
    "подъезд", "под", "под.", "п",

    # Этажи
    "этаж", "эт", "эт.",
]
```

### Правила

1. **Все слова в нижнем регистре** — проверка идет через `text.lower()`
2. **Включены полные названия и сокращения** — "улица" и "ул", "дом" и "д"
3. **Точки включены как отдельные варианты** — "ул" и "ул." — оба варианта
4. **Однобуквенные сокращения без точки игнорируются** — "к", "п" проверяются только с точкой или как целые слова

## Алгоритм определения адреса

### Шаг 1: Разделение сообщения

```python
# Пример сообщения:
"""
П/м не греет
Русский акташ Нефтяников 12
15:00
89196265747
"""

# После обработки:
lines = [
    "П/м не греет",              # ← оборудование/проблема
    "Русский акташ Нефтяников 12", # ← адрес
]
# телефон и время уже извлечены
```

### Шаг 2: Классификация строк

Для каждой строки вызывается `looks_like_address(line)`:

```python
looks_like_address("П/м не греет")              # → False (слово "не")
looks_like_address("Русский акташ Нефтяников 12") # → True (цифры + буквы)
```

### Шаг 3: Сборка результата

```python
equipment_lines = ["П/м не греет"]
address_lines = ["Русский акташ Нефтяников 12"]

equipment_problem = "П/м не греет"
address = "Русский акташ Нефтяников 12"
```

## Обработка ошибок

### Сообщение об ошибке для пользователя

**Расположение:** `app/services/telegram_parser/parser_service.py:118-130`

Если адрес не распознан, пользователь получает:

```
⚠️ Не удалось определить адрес

Пожалуйста, укажите адрес с ключевыми словами:
• ул. (улица), д. (дом), кв. (квартира)
• пр. (проспект), пер. (переулок)
• мкр. (микрорайон), корп. (корпус)

Примеры правильных адресов:
• ул. Ленина д. 5 кв. 10
• Русский акташ ул. Нефтяников 12
• мкр. Центральный д. 25
```

### Типы ошибок

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `missing_fields: ["address"]` | Не найдено строк, похожих на адрес | Попросить пользователя добавить ключевые слова |
| `missing_fields: ["equipment_type"]` | Не распознан тип оборудования | Попросить указать технику явно |
| `missing_fields: ["problem_description"]` | Нет описания проблемы | Попросить добавить описание |

## Тестирование

### Быстрый тест функции `looks_like_address`

```bash
source venv/bin/activate
python3 -c "
from app.services.telegram_parser.patterns import looks_like_address

test_cases = [
    ('Русский акташ Нефтяников 12', True),
    ('ул. Ленина 5', True),
    ('не крутит барабан', False),
]

for text, expected in test_cases:
    result = looks_like_address(text)
    status = '✅' if result == expected else '❌'
```
