## [v2.10.0] - 2025-11-26

### ✨ Новые функции

#### Добавлено
- ♻️ **Восстановление отклонённых заявок (REFUSED → NEW)**:
  - Добавлена кнопка "♻️ Восстановить заявку" для заявок со статусом REFUSED (только для администраторов)
  - Реализован метод `restore_refused_order` в базе данных с полной валидацией через State Machine
  - Создан двухэтапный процесс восстановления: подтверждение → выполнение
  - При восстановлении автоматически:
    - Изменяется статус REFUSED → NEW
    - Очищается поле `refuse_reason`
    - Снимается назначенный мастер (`assigned_master_id = None`)
    - Создаётся запись в истории статусов (`OrderStatusHistory`)
    - Добавляется запись в audit log
    - Отправляется уведомление в группу диспетчеров
  - Обработчики:
    - `callback_restore_order` - запрос подтверждения с отображением информации о заявке
    - `callback_confirm_restore_order` - выполнение восстановления
  - Интеграция с модулем поиска заказов (Order Search)
  - Кнопка восстановления отображается только для администраторов в результатах поиска

#### Технические детали
- Файлы изменений:
  - `app/keyboards/inline.py` - добавлен параметр для отображения кнопки восстановления
  - `app/database/orm_database.py` - метод `restore_refused_order` с полной валидацией
  - `app/handlers/admin.py` - обработчики для процесса восстановления
  - `app/handlers/order_search.py` - передача статуса и роли для отображения кнопки
- Используется существующая State Machine для валидации перехода REFUSED → NEW
- Права доступа: только ADMIN и DISPATCHER согласно `OrderStateMachine.ROLE_PERMISSIONS`

### 📋 Бизнес-логика
- Восстановленная заявка возвращается в общий пул новых заявок
- Администратор может сразу назначить мастера на восстановленную заявку
- История изменений полностью сохраняется (включая старую причину отказа)
- Диспетчеры получают уведомления о восстановлении заявки:
  - **Личные уведомления** всем диспетчерам из `DISPATCHER_IDS` (уже настроено в env)
  - **Уведомление в группу** (опционально, если настроено `DISPATCHER_GROUP_ID`)

### ⚙️ Конфигурация
- Используется существующий список `DISPATCHER_IDS` для отправки личных уведомлений диспетчерам
- Добавлена опциональная переменная окружения `DISPATCHER_GROUP_ID` в `Config`:
  - Для отправки уведомлений в группу диспетчеров (дополнительно к личным)
  - Если не настроено - отправляются только личные уведомления диспетчерам
  - Примеры конфигурации добавлены в `env.city1` и `env.city2`
  - Получите ID группы с помощью @userinfobot или @RawDataBot (опционально)

## Формат

- **Добавлено** - новый функционал
- **Изменено** - изменения в существующем функционале
- **Устарело** - функционал, который скоро удалят
- **Удалено** - удаленный функционал
- **Исправлено** - исправления багов
- **Безопасность** - изменения безопасности

## Как использовать версии

### Создание новой версии (на локалке):
```bash
make git-release VERSION=v1.4.0 MSG="описание изменений"
```

### Деплой версии (на сервере):
```bash
make prod-deploy-version VERSION=v1.3.0
```

### Просмотр всех версий:
```bash
git tag -l
```
